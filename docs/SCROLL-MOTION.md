# Opt-in scroll motion v1

Set `site.json.scrollMotion` to `{"version":1,"policy":"enabled"}` and use stable `id` plus `data-motion` attributes. Read `agent/refs/motion.md` for the complete engine-independent contract and original recipe command. Native HTML, blocks-v0 components and composition-v1 share the contract after flattening.

Keep the site's operator restrictions. `scrollMotion.policy:"off"` disables all effects. Legacy `motion.strength:"off"` remains a default which a legacy per-instance `motion` overrides. Omitted new configuration preserves legacy behavior and does not enable new markers. Component roots with explicit new markers avoid automatic reveal wrappers. Do not hide a primary hero or entire page.

Motion remains a versioned opt-in. Managed-kit updates distribute `refs/motion.md` through normal scaffold and upgrade hashing, with custom instructions preserved as conflicts/overrides. Run `vitris upgrade --site SITE --plan` before `--apply`. Older completed graphs remain pinned until an explicit audit; an instruction upgrade does not silently migrate customer motion policies or their graph.

Disable the new policy and rebuild to roll back motion. Remove markers for a completely static route. No production deployment, customer migration or human preference promotion is performed by this implementation.

Benchmark command: `node scripts/scroll-motion-benchmark.mjs RUN_DIRECTORY`. Install the pinned benchmark-only dependencies into that directory first. Never add both libraries to the production package. The protocol is frozen before measured results; changed source requires a fresh run directory. Recording and performance runs stay separate. Raw trace/JSON, failures, environment, descriptive spread and uncertainty belong in the run directory; five runs are not statistical proof.

Browser verification defaults to both normal and reduced modes, retains static/accessibility/navigation/media/form checks, and binds temporal scenarios and captures to source, output and runtime. Use `--motion normal|reduce` for diagnostics; those partial runs cannot satisfy the motion gate on enabled routes. Use recordings for aesthetic review and performance traces for measured cost. Never use a final screenshot to claim temporal quality or agent assessment as human preference.

`npm run build:cli` regenerates the selected browser bundle from `docs/scroll-motion-engine.json`. Its SHA-256 determines `/motion-HASH.js`; local builds and Worker preview/publish compilation emit the same bytes. Quiet routes and the cookie page do not request it. Runtime changes require a rebuild and new browser evidence. `window.VitrisMotion.init()`, `.dispose()` and `.inspect(id)` support host lifecycle/debugging; the compiler owns stable target bindings. No vendor is fetched from a CDN.

Generate runnable original teaching with `node --experimental-strip-types scripts/scroll-motion-recipes.ts RUN/recipes`, and isolated customer comparisons with `node --experimental-strip-types scripts/scroll-motion-pilots.ts SOURCE_REPO RUN/pilots`. The pilot generator refuses an existing directory. Serve both with `node --experimental-strip-types scripts/scroll-motion-gallery.ts RUN 4186`. Record pilot evidence with `scroll-motion-evidence.ts` only after performance runs finish. Recording costs are never included in scoring. ReferenceRecord/ReferenceStudy accept optional motionTags and hash-bound temporalEvidence; existing catalog pins and unrelated expansion work remain intact.

Run focused behavior with `node --experimental-strip-types --test src/scroll-motion.test.ts src/scroll-motion-browser.test.ts`; these files also belong to the full official suite. Then run `npm run test:freeze` against stable source, following `docs/OFFICIAL-TEST.md`. A partial diagnostic or failed freeze is not engineering readiness. Static rollout is restored by the explicit off policy and rebuild; instruction upgrades do not change existing site configuration.

The selected production bundle measures 6,082 minified bytes / 2,710 gzip bytes. The matched 240-run benchmark and 40-run deciding-case replay found Motion scripting differences within descriptive spread; GSAP used materially more scripting in both deciding cases. Vanilla therefore wins the size/maintenance tie-break. This does not establish universal smoothness, physical-phone coverage or field INP. See `artifacts/scroll-motion/20261005-implementation/engine-decision.html` for raw-run links and uncertainty.

Initialization waits for document readiness so deferred module UI is present before geometry reads. The existing beacon precedes the motion request. Final shipped profiling retained one first-visit Best Insurance Pro mobile cookie-banner CLS event (0.214, one of five enhanced runs; zero of five static runs). Fifteen controls with an existing Reject choice had zero CLS in static, enhanced and reduced modes. The first-visit interaction remains a promotion risk; layout/content/media were held fixed and the unrelated consent UI was not redesigned. All twelve pilot route/viewport asset checks meet the prescribed budgets. Recordings remain separate from timing runs.

Managed upgrades require closing an active prepared stage first; cancel/restart through the lifecycle before applying an instruction upgrade. Existing valid legacy presets remain supported, while primary, sticky, overly tall and nested reveal wrappers use a readable static presentation. Rebuild and reverify each opted-in site; do not silently migrate existing operator policies. Agent critique and automated checks provide engineering evidence; absent human labels remain unlabeled.
