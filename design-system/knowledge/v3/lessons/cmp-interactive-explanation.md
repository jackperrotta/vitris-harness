# Let visitors investigate a real question

ID: cmp-interactive-explanation. Sources: [S20](https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/), [S30](https://web.dev/articles/vitals), [S32](https://www.gov.uk/service-manual/technology/using-progressive-enhancement).

Teach interaction as a way to compare supported options, inspect a real before/after, explore service reach, or understand a documented relationship. Define the model and its limits first.

Application A: an authentic before/after pair offers an accessible control and static access to both images. Application B: a service guide maps stated needs to relevant explanations without pretending to diagnose or quote.

Counterexample: a slider produces impressive estimates with no supported underlying model.

Mobile: provide working controls, keyboard access, static equivalents, and responsive feedback.

Storyboard: record question, inputs, mapping, fallback, and expected action. Review: test representative and edge inputs, factual boundaries, and actual outputs rather than visual polish alone.

## Authority and use

This is an original design-teaching hypothesis. It is advisory and does not change factual, accessibility, or functional requirements. Adapt it to verified business evidence and inspect the current render before accepting an outcome. The applications above are contrasting examples, not copyable site presets.
